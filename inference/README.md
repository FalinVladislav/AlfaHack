# AI-сервис для бэкенда

Отдельный Docker-сервис `inference` вызывает модели через OpenAI-совместимый Chat Completions API. Зависимости — только стандартная библиотека Python 3.10+. БД и история диалогов остаются у бэкенда.

## Запуск

В корневом `.env` уже используется `API_TOOKEN_CLUB`. Существующий файл не перезаписывайте. Необходимые настройки приведены в корневом `.env.example`:

```dotenv
API_TOOKEN_CLUB=<ключ>
OPENAI_BASE_URL=https://tooken.club/v1
OPENAI_MODEL=gpt-5.6-terra
OPENAI_TIMEOUT_SECONDS=60
OPENAI_MAX_COMPLETION_TOKENS=4096
MODEL_API_TIMEOUT_SECONDS=70
```

URL и публичный ID модели взяты из [FAQ провайдера](https://tooken.club/faq) и [каталога](https://tooken.club/). Доступность модели зависит от ключа и баланса. Для другого совместимого провайдера измените `OPENAI_BASE_URL`, `OPENAI_MODEL` и значение ключа `API_TOOKEN_CLUB`.

```powershell
docker compose up --build -d
```

Бэкенд по умолчанию обращается к `http://inference:8090`; текущий `POST /api/v1/assistant/messages` продолжает использовать `/v1/chat`. `MODEL_API_URL` позволяет переопределить адрес. Ключ передается только контейнеру inference, не бэкенду и не браузеру. Порт сервиса не публикуется на хосте. При отсутствии ключа приложение запускается, а запросы к модели получают 503.

Для локального запуска без Docker установите переменные окружения из примера и выполните `python inference/server.py`. Python не читает `.env` автоматически. Бэкенду задайте `MODEL_API_URL=http://localhost:8090` и таймаут 70 секунд. В Docker загрузку корневого `.env` выполняет Compose.

## Контракт API

Машиночитаемая спецификация: [openapi.json](openapi.json), также `GET /openapi.json` внутри сервиса. Файл можно импортировать в Swagger Editor или Postman. Примеры запросов не обращаются к провайдеру сами по себе.

| Метод и путь | Назначение |
| --- | --- |
| `GET /health` | Состояние процесса и наличие конфигурации; не проверяет модель платным запросом |
| `POST /v1/chat` | Совместимость с существующим `HttpLanguageModel`: instructions + message → intent + answer + proposed_fields |
| `POST /v1/assist` | Все новые сценарии, бизнес-контекст, история, гипотезы, вопросы, продукты и кнопки |

`Content-Type: application/json`. Тело не более 128000 байт. Сообщение — до 16000 символов. Потоковая выдача и автоматические повторы не используются. Не более восьми одновременных запросов к провайдеру на процесс; далее 503 `SERVICE_BUSY`.

Пример запроса бэкенда к `/v1/assist`:

```json
{
  "scenario": "growth_hypotheses",
  "message": "Как увеличить выручку кофейни?",
  "context": {
    "business": {"industry": "coffee_shop", "locations": 1, "monthly_revenue_rub": 900000},
    "calculations": {"free_cash_flow_rub": 120000},
    "products": []
  },
  "history": [],
  "available_actions": [{"action_id": "open_financing", "label": "Подобрать финансирование"}]
}
```

Пример формы ответа (содержимое генерируется моделью):

```json
{
  "scenario": "growth_hypotheses",
  "answer": "Можно проверить спрос на утренние наборы. Для оценки второй точки не хватает данных о затратах.",
  "questions": ["Каковы средний чек и число гостей утром?"],
  "hypotheses": [{
    "title": "Утренний набор: кофе и завтрак",
    "rationale": "Предположение: набор увеличит средний чек; данных о текущих продажах пока нет.",
    "experiment": "Провести двухнедельный тест в текущей точке",
    "success_metric": "Рост валовой прибыли утренних продаж относительно сопоставимых дней"
  }],
  "product_ids": [],
  "actions": []
}
```

`history`: до 30 сообщений `{role: user|assistant, content: string}` в хронологическом порядке. Бэкенд хранит историю и передает нужное окно на каждом шаге; сервис ничего не сохраняет. `context` — расширяемый объект. `business` содержит доступные сведения о бизнесе, `calculations` — результаты расчетов бэкенда с единицами и датами; `products` — актуальные предложения с уникальными строковыми `id`, условиями и ограничениями; `documents` — извлеченный текст и назначение документов; `knowledge` — проверенные справочные материалы. Бинарные файлы не принимаются: извлечение текста выполняется до вызова сервиса.

| scenario | Применение |
| --- | --- |
| `growth_hypotheses` | Гипотезы роста с обоснованием, экспериментом и метрикой |
| `consultation` | Открытие второй точки, обсуждение бюджета и доступности кредита |
| `cash_gap` | Объяснение разрыва по обязательствам, поступлениям и датам |
| `contract` | Объяснение переданного договора |
| `documents` | Зачем нужны документы и как их предоставить |
| `navigation` | Помощь в интерфейсе и предложения кнопок |
| `bureaucracy` | Разбор процедур по переданным инструкциям |
| `staff_summary` | Резюме клиента для сотрудника банка |
| `onboarding` | Последовательный опрос о бизнесе с уточняющими вопросами |
| `product_selection` | Подбор из переданного каталога продуктов |
| `reference` | Справочник по переданной базе знаний |

Для кнопки загрузки справки передайте, например, `available_actions: [{"action_id":"upload_statement","label":"Загрузить выписку"}]`. Сервис возвращает только разрешенный `action_id` и исходную подпись. Связь ID с маршрутом/эндпоинтом задается в бэкенде или UI; модель не определяет URL, HTTP-метод или параметры запроса. Фактическое действие выполняется после выбора пользователем с обычной проверкой прав и CSRF. Неизвестный ID продукта или действия в структурированном ответе отклоняется целиком.

Новые сценарии доступны на внутреннем API. Их подключение к пользовательским экранам и сбор контекста из БД — ответственность вызывающего бэкенда; существующий кредитный чат подключен автоматически через прежний контракт. Сервис не загружает каталог Альфы из интернета: актуальные предложения передает бэкенд. Проверка ID не проверяет достоверность свободного текста ответа.

## Ошибки и границы

Ошибка: `{"code":"..."}`. 400 `INVALID_REQUEST`; 413 `INVALID_SIZE`; 415 `UNSUPPORTED_MEDIA_TYPE`; 502 `INVALID_MODEL_RESPONSE` / `PROVIDER_ERROR`; 503 `MODEL_NOT_CONFIGURED`, `MODEL_UNAVAILABLE`, `PROVIDER_RATE_LIMITED`, `PROVIDER_ERROR`, `SERVICE_BUSY`; 504 `PROVIDER_TIMEOUT` (или `MODEL_UNAVAILABLE` при сетевом таймауте); 500 `INTERNAL_ERROR`. Секреты и тело ошибки провайдера не возвращаются. Нет молчаливого переключения на другую модель.

API предназначен для внутренней сети Compose без прямого доступа браузера. Бэкенд проверяет пользователя, принадлежность контекста компании и право сотрудника на `staff_summary` до передачи данных. Сервис не имеет пользовательской авторизации. Передавайте только необходимые данные: контекст уходит внешнему провайдеру. Модель объясняет готовые финансовые расчеты и предлагает гипотезы; финансовый расчет и кредитное решение остаются за бэкендом.

Проверки без внешнего API: `python -m unittest discover -s inference -v`. Тесты поднимают настоящий локальный HTTP-провайдер и проверяют передачу ключа, формат, валидацию, ошибки и совместимость чата.
