# Бизнес-сценарии через диалог и tools

На странице суммы и срока появился помощник. Он собирает параметры проекта, уточняет неизвестное и запрашивает расчёт. Предложенный план показывается с числами и диапазонами; только кнопка подтверждения применяет его к основному графику. До подтверждения доступны прежние сценарии по истории бизнеса. Перезагрузка страницы восстанавливает обсуждение и подтверждённый план.

## Общая модель

Это ограниченный язык зависимостей, а не генерация исполняемых формул моделью. `SALES` описывает существующий или новый канал: продажи = минимум спроса, мощности, возможностей персонала и доступных ресурсов. Цена, затраты на единицу и постоянные расходы дают денежный поток; считается только разница будущего состояния и текущего. У нового канала текущее состояние нулевое. `CASHFLOW` описывает дополнительные доходы, расходы, экономию и потерю выручки. Компоненты суммируются: они обязаны быть независимыми; связанные изменения одной точки нужно объединять. Семантическую независимость проверяют помощник и пользователь, автоматической проверки причинности нет.

Одна модель подходит для оборудования, новой точки, найма, закупок, маркетинга и экономии, когда известны соответствующие параметры. Неизвестные параметры возвращаются как `NEEDS_INPUTS`; неизвестное нельзя автоматически заменять нулём. Произвольные зависимости и код не исполняются. Если цель не описывается поддерживаемыми зависимостями, нужны явные денежные допущения либо расширение модели.

Для инвестиции, задержки запуска и будущих параметров задаются `{low,base,high}`. Неблагоприятный сценарий берёт нижние доходы/ресурсы и верхние затраты/задержку, благоприятный — наоборот. Дополнительные коэффициенты старой модели 50%/120% не применяются. Проектный поток начинается после запуска и далее постоянен; помесячная раскрутка, обучение персонала, налоги по отдельным режимам, амортизация и обратные связи не выводятся автоматически. Их необходимо включать в подтверждённые параметры или расширять модель. Вероятности исходов и причинный эффект не обучались и не оценены. Базовый исторический поток по-прежнему использует среднее последних полных месяцев и известный календарь; это условная симуляция, не гарантия результата.

## API для бэкенда и UI

Все пути с префиксом `/api/v1`, сессия обязательна, для POST нужен CSRF.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/drafts/{id}/scenario-dialog` | Статус, видимая история, предложенный и подтверждённый планы; без записи |
| POST | `/drafts/{id}/scenario-dialog/prepare` | `{working_plan_hash}`; восстановить полностью заполненный рабочий план для проверки, без подтверждения и LLM |
| POST | `/drafts/{id}/scenario-dialog/messages` | `{message, quote_id, request_id}`; сохраняет сообщение и ставит работу в очередь |
| POST | `/drafts/{id}/scenario-dialog/retry` | Повтор после сбоя, история остаётся |
| POST | `/drafts/{id}/scenario-dialog/confirm` | `{plan_version}`; подтверждение конкретной версии полного плана |
| POST | `/quotes/{id}/business-scenarios` | `{plan_version}`; три сценария по подтверждённому плану и актуальному расчёту кредита |

Диалог привязан к пользователю, компании, черновику и снимку цели. Смена суммы/срока сохраняет экономику проекта, смена цели создаёт отдельное обсуждение без старого подтверждения. Доступ к чужим черновикам и устаревшим расчётам запрещён. `request_id` делает повтор отправки сообщения идемпотентным. Статусы: `NOT_STARTED`, `IDLE`, `QUEUED`, `RUNNING`, `FAILED`. Во время работы UI опрашивает GET, без перезагрузки страницы.

`business_scenario_dialogs` хранит всю историю Chat Completions, включая calls/results, рабочий неполный план, предложенный и подтверждённый планы, версии и состояние очереди. `business_scenario_runs` хранит снимки входов и результаты. В модель отправляются текущий контекст, рабочие параметры и последние пять пользовательских ходов вместе с полными цепочками tools. Полный журнал остаётся в БД. Ограничение диалога — 600 сообщений, модельного контекста — 90 КБ плюс схемы tools.

Worker обрабатывает один модельный шаг за раз, без долгой транзакции на HTTP. Lease восстанавливает незавершённую работу после перезапуска. Ограничение — четыре модельных шага и до трёх инструментов за шаг на одно сообщение. Ошибки провайдера не раскрываются пользователю, автоматического бесконечного повтора нет. Отключение worker: `SCENARIOS_WORKER_ENABLED=false`.

## Внутренний inference API

`POST /v1/tools`: `{messages,tools}` → `{message,finish_reason,model}`. Использует нативные `tools`, `tool_choice:auto`, `parallel_tool_calls:false` в Chat Completions. Разрешены только `get_business_context`, `get_missing_inputs`, `simulate_scenarios`. Сервис проверяет имена, идентификаторы и связь tool results; сам не исполняет tools и не обращается к БД. Бэкенд повторно проверяет аргументы и выполняет расчёты. Доступ к данным всегда определяется авторизованным пользователем, идентификаторы компаний модель не задаёт. Ключ провайдера остаётся в inference.
