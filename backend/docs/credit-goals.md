# Выбор цели кредита

Первый шаг оформления предлагает список готовых целей. «Другое» скрывает список и открывает описание (5–500 символов). К списку можно вернуться без потери текста.

| Цель | Направление | Продукты текущего каталога |
| --- | --- | --- |
| Купить оборудование | EXPANSION | DEVELOPMENT, DEVELOPMENT_RATE, DEVELOPMENT_FLEX |
| Открыть новую точку | EXPANSION | DEVELOPMENT, DEVELOPMENT_RATE, DEVELOPMENT_FLEX |
| Расширить или отремонтировать помещение | EXPANSION | DEVELOPMENT, DEVELOPMENT_RATE, DEVELOPMENT_FLEX |
| Закупить товары или сырьё | WORKING_CAPITAL | WORKING_CAPITAL |
| Оплатить текущие расходы | WORKING_CAPITAL | WORKING_CAPITAL |
| Закрыть временный кассовый разрыв | CASH_GAP | OVERDRAFT |

Готовая цель сопоставляется по таблице без LLM. Количество целей не обязано совпадать с количеством направлений или продуктов. Три направления — состав текущего проекта, а не полный перечень банковских кредитов. Добавление нового направления требует его описания, продуктов, условий, расчётов и поддержки в оформлении.

## Свободный текст

1. Бэкенд передаёт LLM описание и определения допустимых направлений через `/v1/chat` сервиса inference.
2. Модель возвращает JSON: CLASSIFY_GOAL с proposed_fields.purpose, CLARIFY_GOAL с вопросом либо UNSUPPORTED_GOAL. Учитываются смысл, временной характер потребности, отрицания и несколько самостоятельных целей.
3. Сервер принимает только известный purpose. Неизвестная категория или некорректный ответ приводит к уточнению. Суммы, продукты и ставки из ответа модели не применяются.
4. Пользователь подтверждает предложенное направление. Можно уточнить описание или самостоятельно выбрать другое из разрешённых.
5. Только после подтверждения изменяется черновик. Продукты и доступные параметры определяются каталогом и `/financing/limits` по данным компании.

Например, аренда до ожидаемой оплаты клиента — временный кассовый разрыв. Регулярные текущие расходы без такого разрыва — оборотные средства. При недоступности LLM используются ограниченные правила; отрицания, смешанные или непонятные цели и временные признаки в текущих расходах требуют уточнения. Неопределённому описанию не назначается развитие бизнеса по умолчанию.

## API и хранение

- `GET /api/v1/financing/goals` — готовые цели с product_ids.
- `POST /api/v1/financing/resolve-goal` — `{ "goal_id": "STOCK" }` или `{ "goal_id": "OTHER", "text": "..." }`. Требуются клиентская сессия и CSRF.
- `READY` содержит goal_id, goal_text, purpose, purpose_label, product_ids, source и choices; черновик не создаётся.
- `NEEDS_CLARIFICATION` и `UNSUPPORTED` содержат question и choices; purpose не назначается.
- Подтверждённые goal_id и goal_text сохраняются обычным PATCH черновика с expected_version. Готовая цель проверяется на соответствие тексту и направлению. При смене назначения без новой цели устаревшие метаданные сбрасываются.

Классификация получает только пользовательское описание и определения направлений; финансовые данные для неё не передаются. Она не является кредитным решением. Фоновые гипотезы работают независимо.
