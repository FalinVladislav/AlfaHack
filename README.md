# Умный кредитный кабинет предпринимателя

Локальная система кредитного пути МСП: персональные сценарии финансирования, подача заявки с выбором условий, список заявок и кредитов, доходы и расходы. Сотрудник запускает проверки на синтетических профилях; решение объясняется пятью метриками. Данные сохраняются в БД после обновления страницы и перезапуска API.

## Быстрый запуск

Нужен запущенный Docker Desktop с Linux-контейнерами. Из корня проекта:

```powershell
Copy-Item .env.example .env
docker compose up --build -d
```

Откройте `http://localhost:8088`. API доступен внутри Compose; проверка состояния: `http://localhost:8088/actuator/health`. При первом запуске создаются тестовые компании и операции.

Для запуска без Docker нужны Java 21+, Maven 3.6.3+, Node 22+ и npm. Backend использует локальную файловую H2 в `data/`:

```powershell
mvn spring-boot:run
```

Если проект уже собран, Maven для запуска не нужен. Остановите ранее запущенную версию сервера, затем из корня проекта выполните `java -jar .\target\smart-credit-cabinet-1.1.0.jar`.

В другом терминале:

```powershell
cd web
npm ci
npm run dev
```

Откройте `http://localhost:5173`. Если порт API 8080 занят, задайте `PORT=18080` перед запуском Java и `API_PROXY=http://localhost:18080` перед запуском Vite. На PowerShell: `$env:PORT='18080'` и `$env:API_PROXY='http://localhost:18080'` соответственно.

## Ollama

В `.env` укажите имя локально установленной модели с открытыми весами в `OLLAMA_MODEL`. Пример последовательности:

```powershell
ollama pull <имя-модели>
ollama serve
```

Запуск `ollama serve` нужен, если Ollama ещё не работает как служба. Для Compose значение по умолчанию `OLLAMA_URL=http://host.docker.internal:11434`; при локальном запуске Java — `http://localhost:11434`. Адрес, модель и таймаут задаются через `OLLAMA_URL`, `OLLAMA_MODEL` и `OLLAMA_TIMEOUT_SECONDS`. Скачивание весов производится пользователем отдельно; проверьте лицензию выбранной модели и доступную память.

Интеграция вызывает `POST /api/chat` с `stream:false` и JSON-ответом. Backend принимает только разрешённые поля `purpose`, `amount`, `term_months`, `duration_days`, `needed_by`; изменение черновика выполняется отдельным подтверждённым действием. При пустом `OLLAMA_MODEL` или недоступной Ollama помощник сообщает об этом, а форма и заявка продолжают работать.

## Тестовые пользователи и сценарий

На странице входа используйте логин `stable`, `gap` или `staff`. Пароль для всех трёх: `Alfa2026!`. Это только тестовые пользователи; пароли в БД хранятся как PBKDF2-хэши с индивидуальными солями. Регистрации и реальных персональных данных нет.

1. Войдите как `stable`, изучите «Возможности», затем откройте «Подать заявку». Сохраните цель «Развитие бизнеса», сумму 3 000 000 ₽, срок 36 месяцев и дату потребности после 21 октября 2026 года.
2. Рассчитайте варианты, подтвердите согласие и отправьте заявку.
3. Войдите как `staff`, откройте заявку и запустите профиль «Розница» для одобрения либо «Недостаточно данных» для запроса документа. Доступны семь отраслевых кейсов и сценарий ошибки mock-источника.
4. Для `MISSING_INFO` вернитесь под `stable` и загрузите файл `src/main/resources/seed-documents/stable_statement.csv`. После статуса `VERIFIED` нажмите «Продолжить проверку».
5. Примите предложение, откройте договор, подтвердите подписание и получение средств. Кредит остаётся в карточке после обновления страницы.

Профили «Общепит» и «Стройка» показывают условное предложение и отказ. Вход `gap` показывает плановый минимум −120 000 ₽ на 15 ноября 2026 года. Профиль проверки фиксируется при первом запуске и не меняется для этой заявки.

## Проверки

После запуска API выполните:

```powershell
py scripts/smoke.py http://localhost:8080
```

Скрипт создаёт тестовые заявки и проверяет прогноз, права доступа, конфликт версии, повторную подачу, документ, одобрение, отказ, встречное предложение и единственную выдачу. Для сборки: `mvn test` и `cd web; npm run build`. Проверка через скрипт меняет локальные демоданные.

## Устройство проекта

- `src/main/java/org/alfahack` — API, авторизация, генератор профилей, mock-источники, скоринг, заявки, прогноз и адаптер Ollama.
- `src/main/resources/schema.sql` — таблицы, создаваемые при запуске; `SeedData` загружает данные один раз.
- `web/` — React-интерфейс клиента и сотрудника; nginx проксирует API в Compose.
- `data/` — локальная H2 при запуске без Docker. В Compose данные хранятся в томе PostgreSQL; пользовательские файлы не сохраняются.
- `docs/` — архитектура, состояние заявки и контракт API.

Деньги считает сервер с `BigDecimal`. Черновик изменяется с проверкой `expected_version`; предварительный расчёт привязан к версии. Подача, принятие, подпись и выдача используют `Idempotency-Key`. Сессия хранится на сервере в БД; cookie `HttpOnly`, изменяющие запросы требуют `X-CSRF-Token`. Клиент получает только объекты своей компании.

## Границы демонстрации

Все ставки и правила — проектные. Ответы внешних источников воспроизводятся локально, без реальных API. Рекомендации на первом экране — сценарии, а не реальные рыночные новости; Ollama для них пока не нужна. Для подтверждения данных принимается только приложенная синтетическая CSV-выписка; другие файлы отклоняются без сохранения. БД хранит только её контрольную сумму, содержимое берётся из ресурса проекта. Прогноз использует только известные будущие события, поэтому стрессовый сценарий совпадает с базовым. Шестимесячный ряд показывает конец каждого месяца и не доказывает отсутствие разрыва внутри месяца. Договор, подпись и выдача не имеют юридической или финансовой силы. Реальных банковских переводов нет. Подробные пороги, ошибки и примеры JSON: [политика скоринга](docs/credit-policy.md).

При развёртывании за пределами локальной среды потребуются централизованное управление пользователями, миграции схемы вместо стартового `schema.sql` и аудит инфраструктуры. Эти задачи не входят в текущий запуск.
