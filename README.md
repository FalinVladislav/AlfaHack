# Умный кредитный кабинет предпринимателя

Локальная система кредитного пути МСП: клиент отправляет заявку, система рассчитывает риск и рекомендацию, ответственный сотрудник принимает решение, клиент принимает конкретное предложение и подписывает договор. После подписи система имитирует одну выдачу кредита. Данные сохраняются в БД после обновления страницы и перезапуска API.

## Быстрый запуск

Нужен запущенный Docker Desktop с Linux-контейнерами. Из корня проекта:

```powershell
Copy-Item .env.example .env
docker compose up --build -d
```

Откройте `http://localhost:8088`. API доступен внутри Compose; проверка состояния: `http://localhost:8088/actuator/health`. При первом запуске создаются тестовые компании и операции.

### Docker в режиме разработки

Dev-конфигурация запускает Vite с HMR и Spring Boot с автоматической перекомпиляцией и перезапуском после изменений в `backend/src` и `backend/docs`:

```powershell
docker compose -f compose.yaml -f compose.dev.yaml up --build
```

Frontend доступен на `http://localhost:5173`, backend — на `http://localhost:8080`, PostgreSQL — на `localhost:5432`. Порты можно изменить через `DEV_WEB_PORT`, `API_PORT` и `DB_PORT` в `.env`. Кэши Maven, `node_modules` и скомпилированные классы хранятся в именованных Docker-томах и не попадают в рабочее дерево. Остановить окружение можно через `docker compose -f compose.yaml -f compose.dev.yaml down`; для удаления также и dev-томов добавьте `-v`.

Для запуска без Docker нужны Java 21+, Maven 3.6.3+, Node 22+ и npm. Backend использует локальную файловую H2 в `data/`:

```powershell
cd backend
mvn spring-boot:run
```

Если проект уже собран, из папки `backend` выполните `java -jar .\target\smart-credit-cabinet-1.1.0.jar`. При запуске из этой папки H2 использует прежний каталог `data/` в корне репозитория.

В другом терминале:

```powershell
cd frontend
npm ci
npm run dev
```

Откройте `http://localhost:5173`. Если порт API 8080 занят, задайте `PORT=18080` перед запуском Java и `API_PROXY=http://localhost:18080` перед запуском Vite. На PowerShell: `$env:PORT='18080'` и `$env:API_PROXY='http://localhost:18080'` соответственно.

## Swagger для frontend-разработчиков

- Docker Compose: [Swagger UI](http://localhost:8088/swagger-ui/index.html).
- Локальный backend: [Swagger UI](http://localhost:8080/swagger-ui/index.html).
- Vite с запущенным backend: [Swagger UI](http://localhost:5173/swagger-ui/index.html).
- OpenAPI YAML для импорта в Postman или генерации клиента: `/api-docs/openapi.yaml` на том же адресе.

В Swagger UI раскройте `POST /auth/sessions`, нажмите **Try it out**, затем **Execute**. Пример уже содержит `stable` / `Alfa2026!`; можно выбрать `gap` или `staff`. Cookie сессии сохраняется браузером, CSRF-токен добавляется автоматически. Можно также открыть Swagger после обычного входа в приложение на том же адресе. Для изменяющих запросов защита CSRF не отключалась; операции с `Idempotency-Key` требуют заполнения этого заголовка. Не задавайте cookie вручную через Authorize: она HttpOnly и устанавливается сервером.

Источник контракта — `backend/docs/openapi.yaml`: Maven упаковывает его в JAR без отдельной копии в исходниках. Swagger UI также входит в сборку и не требует CDN или внешнего валидатора. После изменения контракта пересоберите backend; в Docker — `docker compose up --build -d`. Схема поддерживается вручную, при изменении API обновляйте этот файл. Не публикуйте демонстрационный Swagger и учётные данные во внешнюю среду без настройки доступа.

Проверки: `mvn -f backend/pom.xml test` и `node --test scripts/tests/swagger-ui.test.cjs`.

## API моделей

На первом шаге оформления работает [выбор цели кредита](backend/docs/credit-goals.md): готовый список или «Другое» с описанием своими словами. LLM предлагает направление для свободного текста, пользователь подтверждает его, затем применяются каталог продуктов и финансовые ограничения. Неоднозначная цель требует уточнения.

Механизм [формирования гипотез](backend/docs/hypotheses.md) работает в фоне: правила находят основания в данных, LLM объясняет каждую гипотезу, бэкенд рассчитывает предварительные кредитные варианты. Главная получает карточки без перезагрузки, подробности открываются на отдельной странице, уведомления — в колокольчике. Статусы заданий и новые методы `/hypotheses` и `/notifications` описаны в Swagger.

Сумма и срок в калькуляторе ограничиваются [данными компании и условиями продукта](backend/docs/financing-limits.md). Серверный метод `/financing/limits` возвращает доступные сочетания; котировки повторно проверяют их перед созданием.

AI-сервис [inference](inference/README.md) подключён к Docker Compose отдельно от бэкенда. По умолчанию он вызывает `gpt-5.6-terra` через Tooken Club с ключом `API_TOOKEN_CLUB` из корневого `.env`. Backend использует `LanguageModel` и `POST /v1/chat` по адресу `http://inference:8090`. Адрес можно переопределить через `MODEL_API_URL`, таймаут — `MODEL_API_TIMEOUT_SECONDS` (по умолчанию в Compose 70 секунд). Для новых сценариев есть `POST /v1/assist`: гипотезы роста, консультации, объяснение кассового разрыва, документы, договоры, опрос и подбор продуктов. Контракт для команды бэкенда: [OpenAPI](inference/openapi.json).

Backend принимает только разрешённые поля `purpose`, `amount`, `term_months`, `duration_days`, `needed_by`; изменение черновика выполняется отдельным подтверждённым действием. При недоступном сервисе помощник сообщает об этом, а форма и заявка продолжают работать. Локальный Maven/Java использует переменные окружения; без `MODEL_API_URL` помощник отключён. Корневой `.env` читает Docker Compose; пустой `MODEL_API_URL` в нём включает адрес `http://inference:8090` по умолчанию.

## Тестовые пользователи и сценарий

На странице входа используйте логин `stable`, `gap`, `staff` или `staff2`. Пароль: `Alfa2026!`. Это только тестовые пользователи; пароли в БД хранятся как PBKDF2-хэши с индивидуальными солями. Регистрации и реальных персональных данных нет.

1. Войдите как `stable`, изучите «Возможности», затем откройте «Подать заявку». Сохраните цель «Развитие бизнеса», сумму 3 000 000 ₽, срок 36 месяцев и дату потребности после 21 октября 2026 года.
2. Рассчитайте варианты, подтвердите согласие и отправьте заявку.
3. Войдите как `staff`, откройте вкладку «Ожидают решения», возьмите заявку в работу. Карточка показывает исходный запрос, финансовые показатели, обязательства, рекомендацию скоринга и историю.
4. Выберите «Одобрить», «Предложить другие условия» или «Отказать». Для новых условий сервер пересчитает платёж и риск. Заполните обоснование и сообщение клиенту, затем подтвердите решение.
5. Войдите как `stable`, откройте предложение, примите конкретную версию условий, просмотрите договор и подтвердите подпись. Зачисление выполняется автоматически; кредит и график остаются доступны после обновления страницы.

После выдачи откройте «Финансы»: период, тип операции и категория одновременно обновляют итоги, график, структуру расходов и историю. Историю можно пролистывать без ограничения первыми 12 записями. В «Кредитной нагрузке» доступны поиск и страницы кредитов и списаний. Кредит можно назвать по-своему и оплатить ближайший взнос. Оплата здесь имитируется внутри БД: долг, остаток счёта, график и история операций меняются одной транзакцией; внешняя платёжная система не вызывается. Повтор того же запроса с `Idempotency-Key` не создаёт повторного списания. Очередь сотрудника также запрашивает страницы и фильтры с сервера.

Если система запросила выписку, клиент загружает `backend/src/main/resources/seed-documents/stable_statement.csv` и после проверки документа нажимает «Продолжить рассмотрение». Вход `gap` показывает другой подготовленный финансовый профиль. Оценка использует сведения компании из БД, а не выбор профиля сотрудником.

## Проверки

После запуска API выполните:

```powershell
docker compose -f compose.yaml -f compose.dev.yaml run --rm --no-deps api mvn test
docker compose -f compose.yaml -f compose.dev.yaml run --rm --no-deps web npm run build
```

Для проверки работающего API выполните `py scripts/smoke.py http://localhost:8080` (подставьте свой `API_PORT`). Скрипт создаёт одну заявку в локальной БД и проходит путь до выдачи. Интеграционные тесты проверяют участие сотрудника, права доступа, конкурирующие действия, версию предложения, повтор подписи и выдачи, а также восстановление после сбоя. Из корня без Docker: `mvn -f backend/pom.xml test` и `npm --prefix frontend run build`. Архитектурные тесты контролируют отсутствие зависимостей сервисов от Spring, HTTP, JDBC и конкретных адаптеров.

Единый стиль Java-кода задан в `backend/config/java-formatter.xml`: отступы 4 пробела, аннотации и тела методов на отдельных строках, параметры объявлений методов — по одному на строку. Применить форматирование из корня: `mvn -f backend/pom.xml formatter:format`. Проверить без изменения файлов: `mvn -f backend/pom.xml formatter:validate`. Базовые настройки редактора находятся в `.editorconfig`.

## Устройство проекта

Frontend объединяет остаток, доходы и расходы на одной странице финансов с общими фильтрами. Главная и ввод цели занимают высоту окна на десктопе без прокрутки страницы. Карточка «Заявки на кредит» открывает заявки, «Кредитная нагрузка» — действующие кредиты, даты списаний, суммы платежей, личные названия и оплату ближайшего взноса. Сравнение предложений и график платежей в калькуляторе пока скрыты; серверный расчёт и отправка заявки сохранены.

Маскоты находятся в `frontend/public/mascots/`: `manager-transparent.webm` — экран входа, `consultant-transparent.webm` — цель кредита, `guide-transparent.webm` — расчёт. Используются предоставленные прозрачные ролики и отдельные асимметричные SVG-подложки из `frontend/public/shapes/`. Подложки не обрезают голову и руки; нижний край видео и постеров маскируется плавной дугой через `mascot-bottom-curve.svg`. Воспроизведение — обычный HTML `<video>`, без удаления фона, canvas и WebGL-обработки в браузере. На главной используется неподвижный `kons-static.png`: фон удалён встроенным imagegen из присланного изображения, [промпт обработки](previews/mascots/static-cutout-prompt.txt). При ошибке воспроизведения используются прозрачные WebP-постеры. При предпочтении уменьшенного движения видео остаётся на постере или текущем кадре. Вне видимой области и в фоновой вкладке видео приостанавливается. Исходные ролики сохранены; плавность зависит от частоты кадров источника и декодирования браузером. Внешние сервисы при просмотре маскотов не используются.

Для наполнения добавлены [синтетические финансовые таблицы](backend/docs/synthetic-finance.md). Они создаются при старте, повторный запуск не дублирует операции и обязательства. В локальном режиме перезапустите backend после обновления; в Docker выполните `docker compose up --build -d`.

Форматирование frontend: `npm --prefix frontend run format`; проверка оформления: `npm --prefix frontend run format:check`.

- `backend/src/main/java/org/alfahack/core` — общие доменные модели, ошибки, контракты транзакций и сериализации, инфраструктурные адаптеры и сборка зависимостей.
- `backend/src/main/java/org/alfahack/features` — фичи: интерфейсы (`port`), сценарии приложения (`application`), входные HTTP-адаптеры (`adapter/in/web`) и выходные адаптеры БД, ресурсов и API (`adapter/out`).
- `backend/src/main/resources/schema.sql` и `finance-schema.sql` — идемпотентные дополнения схемы БД; `SeedData` загружает подготовленные данные один раз. Для новых функций добавлены поля рекомендации и риска заявки, названия кредитов, платежи и отметки оплаты графика. Старые записи не удаляются.
- `frontend/` — React-интерфейс клиента и сотрудника; nginx проксирует API в Compose.
- `inference/` — отдельный Docker-сервис моделей, OpenAI-совместимый провайдер и контракт API для бэкенда.
- `data/` — локальная H2 при запуске без Docker. В Compose данные хранятся в томе PostgreSQL; пользовательские файлы не сохраняются.
- `backend/docs/` — [архитектура](backend/docs/architecture.md), состояние заявки и контракт API.

Деньги считает сервер с `BigDecimal`. Черновик изменяется с проверкой `expected_version`; предварительный расчёт привязан к версии. Подача, принятие, подпись и выдача используют `Idempotency-Key`. Сессия хранится на сервере в БД; cookie `HttpOnly`, изменяющие запросы требуют `X-CSRF-Token`. Клиент получает только объекты своей компании.

## Границы демонстрации

Все ставки и правила — проектные. Ответы внешних источников воспроизводятся локально, без реальных API. Рекомендации на первом экране — сценарии, а не реальные рыночные новости; модель для них не требуется. Для подтверждения данных принимается только приложенная синтетическая CSV-выписка; другие файлы отклоняются без сохранения. БД хранит только её контрольную сумму, содержимое берётся из ресурса проекта. Прогноз использует только известные будущие события, поэтому стрессовый сценарий совпадает с базовым. Шестимесячный ряд показывает конец каждого месяца и не доказывает отсутствие разрыва внутри месяца. Договор, подпись и выдача не имеют юридической или финансовой силы. Реальных банковских переводов нет. Подробные пороги, ошибки и примеры JSON: [политика скоринга](backend/docs/credit-policy.md).

При развёртывании за пределами локальной среды потребуются централизованное управление пользователями, миграции схемы вместо стартового `schema.sql` и аудит инфраструктуры. Эти задачи не входят в текущий запуск.
