# Умный кредитный кабинет предпринимателя

MVP кредитного конвейера МСП: обзор операций → сигнал риска → дневной прогноз → сравнение финансирования → заявка → автоматические проверки → решение → демонстрационные договор и выдача.

## Запуск

Docker Desktop в режиме Linux-контейнеров. Из корня:

```powershell
docker compose up -d --build
```

Интерфейс: http://localhost:8088. Swagger: http://localhost:8088/swagger-ui/index.html. Health: http://localhost:8088/actuator/health.

После изменения только frontend:

```powershell
docker compose up -d --build --no-deps web
```

База PostgreSQL сохраняется в Docker volume. Старые операции, кредиты и решения не переписываются. Новые демокомпании создаются при старте. Решения по старым заявкам остаются прежними; для новой логики создавайте новую заявку. Профиль старой заявки, не соответствующий компании, отклоняется при повторной проверке.

Для чистого демонстрационного набора без удаления текущей БД запустите отдельный проект:

```powershell
$env:WEB_PORT='8091'
docker compose -p alfahack-demo up -d --build
```

Он откроется на http://localhost:8091 и использует отдельный volume. Основной проект работает на своём порту.

Локальная разработка: Java 21+, Maven 3.6.3+, Node 22+. В одном терминале `mvn -f backend/pom.xml spring-boot:run`, в другом `cd frontend`, `npm ci`, `npm run dev`. В PowerShell при блокировке npm.ps1 используйте `npm.cmd`. Локальный API: 8080, Vite: 5173; API_PROXY меняет адрес API в Vite. H2 хранится в data/ при запуске из backend.

## Демо-сценарии

Пароль всех демоаккаунтов: `Alfa2026!`. Данные синтетические, реальные банковские операции отсутствуют.

| Логин | Компания | Сценарий |
|---|---|---|
| stable | Кофейня Вторая чашка | Устойчивый бизнес, одобрение при достаточном свободном потоке |
| gap | Мастерская Горизонт | Плановый дефицит, подбор краткосрочного финансирования |
| reject | Стройка Север | Отказ из-за просрочки |
| missing | Магазин Новый день | Запрос недостающих сведений |
| counter | Кафе У дома | Встречное предложение с уменьшением суммы |
| staff | Кредитный специалист | Мониторинг, отчёт, исходные значения и история |

На чистой БД для четырёх исходов используйте развитие бизнеса, 1 000 000 ₽, 24 месяца, дату 1 ноября 2026 года. Уже выданные кредиты и сохранённые операции влияют на результат: старый аккаунт stable с другой историей может получить встречное предложение.

1. Войдите как gap: на главной видны прогноз, минимум, дата дефицита и карточка риска. Раскройте причины — плановые операции и списания по кредитам.
2. Нажмите «Подобрать финансирование». Сумма ограничена демонстрационным лимитом продукта; если дефицит больше лимита, график честно показывает остаточный риск.
3. Меняйте сумму, срок, назначение, продукт и дату. Расчёт выполняется сервером после короткой паузы ввода. Переключите 30 дней / 6 месяцев / весь срок. Цвет линии зависит от отрицательного минимума. Наведение или ползунок даты показывает дневные значения. Даты выдачи и платежей отмечены; суммы доступны под графиком.
4. Для заявки заполните согласие. Ответ backend уже содержит решение: вход сотрудника не нужен. Карточка показывает причины, условия, реальные события и следующие действия.
5. Повторите запрос под reject и counter. Встречное предложение можно принять или отклонить.
6. Под missing отправьте заявку, загрузите `backend/src/main/resources/seed-documents/missing_statement.csv`, нажмите «Продолжить проверку». Принимается только этот синтетический ресурс; произвольные документы не подтверждают данные.
7. Под stable примите условия, откройте договор, подтвердите демоподпись и выдачу. Обновите страницу: состояние и кредит сохраняются. Инвестиционная сумма расходуется в день выдачи, не становится свободной прибылью.
8. Под staff откройте заявку: профиль принадлежит заявителю и не редактируется. Доступны исходные показатели, формулы, баллы, стоп-факторы и история.

## Данные и расчёты

Скоринг связан с компанией на сервере. Выбор сотрудником чужого demo_profile отклоняется с PROFILE_LOCKED. Финансовые обороты и прибыль берутся из сохранённых transactions: прибыль = поступления − списания + исторические платежи по действующим кредитам. Это демонстрационная оценка операционного результата; все расходы в наборе считаются операционными. Активы, обязательства, залог и просрочка — известные синтетические снимки, раскрытые в источниках отчёта. Текущая месячная долговая нагрузка включает existing_loans и уже выданные loans. При недостатке истории/источников решение не одобряется автоматически.

Политика использует пять метрик: платежи к выручке, LTV, текущая ликвидность, рентабельность, рост выручки. Отсутствие залога — N/A с частичными баллами, а не максимум. Просрочка и другие стоп-факторы показываются отдельно. Дополнительно платёж ограничен 50% текущего свободного месячного потока. Для длинного кредита это сценарий неизменных месячных показателей на весь срок, а не доказательство будущей выручки. Уменьшенное предложение пересчитывается с BigDecimal. Ставки и пороги учебные.

Прогноз строится по дням: предыдущий остаток + плановые поступления − расходы − платежи по существующим кредитам. Анализ добавляет выдачу и график нового кредита; для инвестиций в день выдачи также вычитает целевой расход. Новая выручка не выдумывается. Для краткосрочного транша возвращается основной долг с процентами за дни; аннуитет не применяется. Длинный горизонт показывает каждый день до погашения, минимум и отрицательные даты, а не только конец месяца.

Прогноз — консервативный план известных событий, не статистическая модель. Повторяющаяся будущая выручка не моделируется, поэтому после окончания расписания поступлений длинный график может уходить в минус. Базовый и стрессовый API-сценарии отличаются: в STRESS ожидаемые поступления уменьшаются на 20%, обязательные платежи не меняются. В интерфейсе нет фиктивного переключателя.

Гипотезы разделены на RISK и OPPORTUNITY. Риск формируется по дневному минимуму и стоит первым; возможность помечена как гипотеза, без обещаний роста и окупаемости. Исторические доходы/расходы отделены от будущего остатка. Платежи к выручке — отдельный показатель, не полная оценка платёжеспособности.

## Архитектура и API

React → nginx → HTTP-адаптеры Spring → входные порты → сценарии → выходные порты → JDBC/PostgreSQL. Локально используется H2. Пакеты фич: auth, finance, forecast, insights, products, drafts, applications, scoring, documents, assistant. Сервисы не зависят от Spring/HTTP/JDBC; это проверяет ArchitectureTest.

Схема, состояния и модель данных: backend/docs/architecture.md, backend/src/main/resources/schema.sql и finance-schema.sql. Канонический OpenAPI: backend/docs/openapi.yaml; Swagger UI упакован в JAR.

SUBMITTED → CHECKING → APPROVED / COUNTEROFFER / REJECTED / NEEDS_INFO. После подтверждения документа NEEDS_INFO → CHECKING. Принятие → OFFER_ACCEPTED → SIGNED → DISBURSED. Отказ клиента → CLOSED. Внутри CHECKING журнал фиксирует ASSESSING_TERMS. Быстрые проверки выполняются в транзакции подачи без искусственных задержек; после сбоя источника возможна повторная проверка. Завершённое решение не пересчитывается.

Черновики имеют optimistic locking; расчёт привязан к версии. Подача, принятие, подпись и выдача используют Idempotency-Key. Переходы блокируют строку заявки, кредит уникален по application_id. Сервер проверяет компанию и роль. Сессия в БД, cookie HttpOnly, изменяющие запросы требуют CSRF. Это локальный прототип: для внешнего развёртывания нужны HTTPS, secure-cookie, управление пользователями, миграции и инфраструктурный аудит.

## Контекстная помощь

Кнопка «Обсудить с ИИ» открывает боковую панель на дашборде, в аналитике, подборе и решении. Backend получает данные текущей компании, прогноз/события, параметры расчёта и причины решения самостоятельно, проверяя принадлежность quote/application. Модель не принимает кредитное решение. При недоступности модели показывается её недоступность; основной процесс работает.

inference/ — отдельный опциональный сервис с контрактом POST /v1/chat, не включён в Compose. MODEL_API_URL и MODEL_API_TIMEOUT_SECONDS настраивают backend; для Docker адрес внешнего локального сервиса — http://host.docker.internal:8090. В inference задаются Ollama и модель с открытыми весами. Платные API не требуются. Панель объясняет контекст; применение предложенных моделью полей доступно через существующий подтверждаемый API.

## Проверки

```powershell
mvn -f backend/pom.xml test
npm.cmd --prefix frontend run build
npm.cmd --prefix frontend run format:check
node --test scripts/tests/swagger-ui.test.cjs
python -m unittest discover -s inference -v
```

Если Maven отсутствует:

```powershell
docker build --target verify -t alfahack-verify ./backend
```

Проверка работающего чистого демонабора (создаёт заявки и выдачу, поэтому меняет его данные):

```powershell
python scripts/smoke.py http://localhost:8091
```

ConveyorIntegrationTest проверяет четыре автоматических исхода, запрет подмены профиля, повторные проверки, доступ к чужой заявке, идемпотентность подачи/выдачи, документ, дневные минимумы, инвестиционный расход и полный срок погашения. Другие тесты проверяют калькулятор, финансы, архитектуру и контракт API. Smoke проверяет HTTP, cookies/CSRF, сохранение и основные пользовательские действия. Графики используют ответы сервера; формулы кредита на frontend не дублируются.
